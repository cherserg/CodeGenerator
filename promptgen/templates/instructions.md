# Правила написания скриптов для ИИ

## Общие правила:

- При проверке скриптов не ленись и не указывай, что что-то там куда-то "схлопывается" при проверке типов. Ничего никуда не схлопывается, надо просто тебе самому внимательно изучить вывод типов;
- Нельзя создавать новые интерфейсы или типы, если в коде уже есть подходящие интерфейсы или типы;
- Не используй тип `any`, т.к. он полностью убивает типизацию. Мне необходима корректная типизация!
- Не используй приведение типов и касты `as any`, `as XXX`. Вместо этого, если в текущем коде есть конфликт типов, укажи, где именно, и как исправить.
  ВАЖНО!!! Ни в коем случае не используй приведение к `as any`!!!

- Не используй подавление ошибок типа `// @ts-expect-error`, вместо этого правь ошибки.
- Не используй комментарии в коде!

- Нельзя залазить в свойства прототипа (по пути `YYY.prototype.XXX`)
- Нельзя использовать костыли типа Reflect для обхода параметров приватности. Если что-то в настройках приватности свойств мешает получить к нему необходимый доступ, добавляй необходимые геттеры либо (в крайнем случае) меняй настройки приватности

- должен быть единственный источник истины - зод-схемы. Если надо добавить дефолты, как-то изменить undefined / null и т.д., надо менять именно зод-схемы, а не "строить надстройки" в юзкейсах, сервисах и прочем. Это обязательно - единый источник истины!
