Инструкция по использованию системы шаблонов и блоков
Эта система позволяет разбивать длинные инструкции для ИИ на переисползуемые модули (блоки), чтобы не дублировать общие правила (например, стиль кода или язык ответов) в разных шаблонах.

1. Настройка проекта
   В файле promptgenerator.json (в корне вашего проекта) должны быть заданы два ключевых параметра:

JSON

{
"promptsFolder": ".prompts",
"nameForTemplates": "library"
}
promptsFolder: Основная папка с вашими шаблонами (те, что вы выбираете в списке VS Code).

nameForTemplates: Подпапка внутри основной, где лежат "строительные блоки". Файлы из этой папки не будут отображаться в списке выбора, чтобы не загромождать интерфейс.

2. Структура файлов
   Рекомендуется организовать файлы следующим образом:

Plaintext

.prompts/
├── refactoring.md <-- Основной шаблон (виден в списке)
├── feature-request.md <-- Основной шаблон (виден в списке)
└── library/ <-- Папка для блоков (скрыта из списка)
├── code-style.md <-- Блок с правилами оформления
├── project-context.md <-- Блок с описанием стека технологий
└── localization.md <-- Блок с правилами языка 3. Синтаксис использования
Чтобы вставить один файл в другой, используйте конструкцию: [[include:имя_файла.md]]

Пример содержимого блоков
library/code-style.md:

Markdown

- Используй только TypeScript.
- Используй функциональный подход.
- Пиши комментарии в стиле JSDoc.
  library/localization.md:

Markdown

- Все ответы и комментарии должны быть только на русском языке.

4. Как писать "итоговый" шаблон
   В основном шаблоне, который вы будете запускать, просто соберите нужные блоки воедино:

Markdown

Как это работает (под капотом):
Поиск: Когда вы выбираете шаблон refactoring.md, скрипт видит тег [[include:code-style.md]].

Приоритет: Сначала он ищет файл в корне .prompts/, а если не находит — заглядывает в папку library/.

Рекурсия: Блоки могут включать в себя другие блоки. Например, code-style.md может внутри себя содержать [[include:naming-conventions.md]].

Защита: Если вы случайно создадите циклическую зависимость (А включает Б, а Б включает А), скрипт выведет сообщение об ошибке вместо того, чтобы зависнуть.
